## Execution & Validation (Highest Priority)

1. **[2026-09-30] Focus-into-view inside a scrollable popover fires a `scroll` event that looks like "user scrolled the page"**
   Do instead: in any window-level capture-phase scroll listener used to auto-close a popover/menu, first check `menuRef.current?.contains(e.target)` and ignore the event if true — otherwise selecting a mid-list option (which auto-scrolls the popover to bring the focused item into view) closes the popover instantly.
2. **`<details open={...}>` closes itself when the JSX branch computes `open` differently across renders (e.g. hardcoded `open` while editing vs `open={someFalseExpr}` while viewing)**
   Do instead: track open/closed as its own state kept in sync via the native `onToggle` event, and use one consistent `open={state}` expression in every render branch — never a literal `open` in one branch and a computed expression in another.
3. **Two same-specificity CSS class selectors (e.g. `.base` and `.base-modifier`) resolve by source order, not by which reads as "more specific"**
   Do instead: when adding a modifier class next to an existing base class, write the selector as `.base.modifier` (combined) so precedence doesn't depend on where it lands in the stylesheet.
4. **`element.click()` via CDP does not reliably reproduce a real user click for outside-click-to-close tests (no guaranteed `mousedown`)**
   Do instead: use `Input.dispatchMouseEvent` (`mousePressed` + `mouseReleased`) at real coordinates when testing "click outside closes X" behavior; `.click()` is fine for direct button/option activation.
5. **A generic feature wired into many pages (header-filter dropdowns, cell editing) hides bugs until tested past the first happy path**
   Do instead: after building the mechanism, test the *second* interaction (reopen, re-edit, re-select) not just the first — most bugs here surfaced only on the second use, not the first.
6. **[2026-09-30] In an auto-layout `<table width:100%>`, setting an input's own `width` does not pin its column — the table re-shares spare width by content size, so the column lands somewhere else**
   Do instead: pin the `<td>` itself (`td.style.width`, removed in the effect cleanup) and give the input `size=1; min-width:0`; verify with a CDP probe that reads `td.getBoundingClientRect().width` before/after, per column, instead of trusting the CSS.
7. **[2026-09-30] A card that stays mounted after an async success (clear/reset, unlike delete which unmounts it) keeps `busy=true` forever if only `catch` resets it**
   Do instead: reset `busy` in `finally`; for every action that doesn't remove the component, test that the buttons re-enable afterwards.
8. **[2026-09-30] New demo seed rows (src/data/demo.js) never reach a browser that already saved that table's localStorage overlay — the user sees an empty category while every clean-profile test passes**
   Do instead: `demoOverlay` merges seed rows the browser hasn't seen (tracked in `<key>.seen`, so rows the user deleted stay deleted); after adding or changing seed data, also test a stale-state profile (save the old rows to `infodept.demo.<table>` first, then load the screen), not only a cleared one.
9. **[2026-09-30] A `<Navigate to="child/grandchild">` inside a `<Route path="child">` resolves relative to the *matched segment*, not the route's own path — landing somewhere unintended and, if a catch-all route redirects back toward it, looping forever ("Maximum update depth exceeded")**
   Do instead: always use an absolute `to="/parent/child/grandchild"` on redirect `Navigate` elements nested more than one level deep, and load every such route once via CDP (`location.pathname` after navigation) as part of verification — the loop only shows up at runtime, never in a build or lint pass.
10. **[2026-10-01] `<input>` cannot wrap text to a second line — it's structurally single-line no matter the CSS, so "make long text wrap instead of overflowing" always means swapping to a `<textarea>`, not styling the `<input>`**
    Do instead: use the shared `AutoGrowText` component (`src/components/AutoGrowText.jsx` — rows=1 textarea, height set to `scrollHeight` in a layout effect, Enter calls `form?.requestSubmit()` so it still behaves like a single-line input) for any free-text field; keep `type="date"`/`type="number"` as real `<input>` (EditableCell already branches on `schemaCol.type` for exactly this). Give any CSS override a selector *more specific* than the pre-existing `textarea.field-input` rule (e.g. the `.auto-grow` class) or it silently loses to that rule's `resize:vertical;min-height:120px`.

## Shell & Command Reliability

1. **Git Bash / MSYS mangles a leading `/` in script args (e.g. `/manuals` route strings) into a Windows path**
   Do instead: prefix with `MSYS_NO_PATHCONV=1` when a node script's argv contains a route-like string starting with `/`.
2. **`cat <<'EOF'` heredocs silently truncate/corrupt long files containing Korean (multi-byte UTF-8) text**
   Do instead: use the Write tool for any file with substantial Korean content; reserve bash heredocs for short ASCII-only snippets. Backslashes are also unsafe here (2026-10-03: `\\n` in a heredoc'd edit script arrived as `\n`, so string matches silently failed) — edit scripts that need `\n`/regex go through the Write tool.
3. **Headless-Chrome CDP test/cleanup pattern that works reliably here**
   Do instead: launch `chrome.exe --headless=new --remote-debugging-port=9222 --user-data-dir=<temp>`, drive via raw WebSocket CDP (Target.createTarget/attachToTarget, Page.navigate+loadEventFired, Runtime.evaluate), and always tear down with PowerShell `Stop-Process` matching the chrome-smoke commandline + `Remove-Item -Recurse -Force` the temp profile dir.
4. **Demo login session key (`infodept.demo.session`) shares the `infodept.demo.` prefix with every per-table overlay key**
   Do instead: when clearing demo overlays for a clean test run, filter out `infodept.demo.session` explicitly (or clear then re-set login) — a blanket prefix-clear silently logs the test out and every subsequent row count reads 0.
5. **[2026-10-01] 실행 중인 Vite 개발 서버 밑의 파일을 `cat a b > file` 처럼 통째로 덮어쓰면 서버가 그 순간의 빈 파일을 캐시해 "does not provide an export named …" 로 앱 전체가 흰 화면이 된다 (파일 자체는 멀쩡)**
   Do instead: 큰 파일을 셸로 다시 쓴 뒤엔 `touch <파일>` 로 변경 이벤트를 다시 내고 `curl localhost:5173/<경로> | wc -l` 로 서버가 실제 내용을 서빙하는지 확인한다. 가능하면 Edit 도구로 부분 수정해 덮어쓰기 자체를 피한다. 테스트 중 "전 화면 에러"가 나오면 코드를 의심하기 전에 이 캐시부터 본다.
6. **[2026-10-01] `.claude/feedback.md` 는 사용자의 진짜 요청이 쌓이는 파일이다 — 사용자가 개발 서버에서 쓰는 중에도 항목이 늘고, 시험이 5173 서버로 POST 하면 가짜 항목이 섞이며(2026-10-02 실제로 8건 섞임), 시작 때 지우거나 끝에 복원하면 그사이 새로 쌓인 요청이 사라진다**
   Do instead: **전체 회귀를 돌릴 때(verify-*.mjs 전부)도 verify-feedback*.mjs·verify-fb-list.mjs 는 5173 에 대고 돌리면 안 된다(2026-10-03: goedu-fb·home-fb·login-fb 도 feedback.md 를 지웠다 — 전체 회귀 전에 반드시 사본을 뜨고 끝나면 파일이 있는지 본다) — 2026-10-02 에 feedback.md 가 통째로 지워졌다(백업 /tmp/feedback.backupN.md 로 복원).** 피드백 모드 시험은 실제 서버가 아니라 **별도 포트의 시험 서버 + 임시 파일**로 돌린다 — 프로젝트 루트에 임시 설정(`feedbackMode({ file: process.env.FB_TEST_FILE })`)을 만들어 `FB_TEST_FILE=<임시경로> npx vite --config <그 파일> --port 5199 --strictPort` 로 띄우고, 시험은 `open({ base: 'http://localhost:5199' })` 로 연다(`open()` 인자 없이 쓰면 5173 으로 간다 — 이번에 그렇게 섞였다). 끝나면 서버·임시 설정 파일을 지운다. 실제 파일을 건드린 흔적이 의심되면 `curl localhost:5173/__feedback` 의 open 개수와 `grep -n "^## "` 로 시험 경로 항목이 있는지 본다. 피드백 처리 턴에는 먼저 `cp .claude/feedback.md` 사본을 뜬다.

## Domain Behavior Guardrails

1. **Google Sheet is the single source of truth; the sync job replaces DB tables wholesale**
   Do instead: any new write path (rentals, manuals, cell edits, future tables) must write the sheet first, then the DB — never DB-only, or the next sync silently reverts it. (2026-10-06) Supabase/PostgREST returns at most 1000 rows per request and silently truncates (students alone is 945) — never `select('*')` a whole table: server code uses `selectAll()` (netlify/lib/supabase-admin.mts), the browser `sel()` in src/lib/api/supabase.js pages by 1000 + id tiebreak. New full-table reads must do the same; test-sync fake DB caps at 1000 to catch regressions. (2026-10-03) The sync itself is defensive and tested with fake sheet/DB in scratchpad `test-sync.mjs`: a tab with missing headers / unreadable / shrunk to <50% (or empty) is *skipped* (summary.skipped → banner "시트에 문제가…", Admin "건너뜀" 열), blank IDs are written back to the sheet (`fillIds`), a running sync blocks a second one, and app write functions call `waitForSync`. A new schema column therefore makes the real sheet's tab skip until the header exists — run `npm run setup:sheet` (scripts/setup-sheet-guards.mjs, also protects/validates columns from schema `options`/`type`) after any schema change.
2. **`shared/sheet-schema.js` drives demo data, seed SQL, sheet generation, sync, and cell-edit validation (`findEditableColumn`, `resolveRef`) — one schema, many consumers**
   Do instead: extend that file first when adding a table/column/edit rule; don't hardcode column lists per-page or per-function.
3. **A column displayed by joining another table (e.g. laptop's "부서", a classroom's grade/class_no shown on TV/cabinet rows) is not a real column of the row's own table**
   Do instead: never mark a joined/derived display column `editable: true` — only genuine own-columns of the row's table (per schema) get inline cell editing; the joined value is edited from its source table's own screen.
4. **Demo mode only persists edits for tables that have a `localStorage` overlay in `src/lib/data.js`'s `overlays` object**
   Do instead: when adding a new editable table, add its overlay there — reading straight from the static `src/data/demo.js` arrays means edits vanish on reload. A new schema column needs no migration: `demoOverlay`'s `fillNewFields` backfills keys missing from saved rows on every `load()`, and a stale extra key (column just removed) is harmless dead data.
5. **[2026-09-30] Manual attachments: bytes live in Storage bucket `manual-files` (demo: IndexedDB), the row's `attachments` text holds `id|name|size` lines; the storage key is an ASCII id, never the original (Korean) file name**
   Do instead: go through `api.uploadAttachment` / `discardAttachments` / `attachmentUrl` and the shared `parseAttachments`/`formatAttachments`; upload from the browser first, then save the row through the sheet-first `manual` function, and discard the uploads if that save fails. A deployed sheet needs the `첨부파일` header and DB needs migration 0003, or the next sync drops the list.
6. **[2026-09-30] Deleting a menu/page can silently orphan data or links that only that screen surfaced (e.g. removing "교직원별 관리" would have hidden the only UI for `소모품`-type rentals, which had real demo rows)**
   Do instead: before deleting a page, `grep` the app for that route/component and for any `itemType`/`linkKey`/table values it uniquely rendered; relocate anything with real records to an existing screen (here: added a 소모품 tab to the 대여 menu) and tell the user about anything left genuinely unreachable (here: the `drive:staff-laptop-sheet` link) instead of silently dropping it.
7. **[2026-10-03] `--focus-ring` 은 이제 버튼과 같은 흰 2px + 진한 2px 링이다(예전 옅은 보라 틴트는 흰 배경 대비 1.16:1 이라 안 보였음)**
   Do instead: 입력칸·검색칸·날짜 칸 초점은 `var(--focus-ring)` 을 그대로 쓴다. 상태를 흐리게 보일 땐 opacity 대신 취소선·배경·아이콘을 쓰고, 붉은 배경 위 글자는 `--ink` 로(옅은 글자색은 4.5:1 미달). 키보드로 입력칸을 닫으면 그 칸 버튼으로 초점을 되돌리고, 알림은 처음부터 있는 빈 `role=status` 영역의 글자만 바꾼다.

8. **[2026-10-01] When a request asks to make a *joined/derived* display column (guardrail #3) genuinely editable, the fix is a new real column on the row's own table, not an exception to #3**
   Do instead: mirror the closest sibling table that already has the same situation (here: `classroom_tvs.location` didn't exist — only `classrooms.location` did — so I added `classroom_tvs.location text` to the schema + migration, exactly matching how `tablet_cabinets.location` already works: own column, falls back to `classrooms.location` when empty). Keeps the generic `editable:true` + `findEditableColumn` cell-edit machinery working with zero special-casing.
9. **[2026-10-01] 표의 추가/수정/삭제 버튼은 `DataTable` 의 `crud` prop 하나로 켠다 — 없으면 예전 그대로(editable 열이 늘 눌러서 고쳐짐), 있으면 기본 읽기 전용 + 검색창 왼쪽 `.crud-bar`**
   Do instead: 새 표에 열 때 ① `shared/sheet-schema.js` 의 `CRUD_TABLES` 에 한 줄(prefix/required/unique 묶음/defaults) ② 삭제 때 따라 지울 자식이 있으면 `netlify/functions/row.mts` 와 `src/lib/data.js` `deleteRow` 양쪽 처리(DB 의 on delete 규칙과 같게 — staff 는 Goedu 교사 계정 cascade·나머지 set null, devices 는 개별 장비가 있으면 삭제 거절) ③ 페이지에서 `crud={{ add, edit, remove, fields, defaults, required, rowLabel, confirmDelete, canRemove }}`. 검증·id 생성·참조 해석(성함/학번/학년-반)은 공용 `prepareNewRow` 만 쓴다(서버·데모 동일). **눌러서 바꾸는 드롭다운 열(SelectCell 등)은 `render: (r, { editing }) => editing ? <SelectCell/> : 글자` 로 만든다** — 안 그러면 읽기 전용인데 드롭다운이 살아 있다. DataTable 이 `render` 를 부르는 모든 곳(셀, 그리고 머리글 필터 값 목록을 만드는 `cellText` — 여기선 `{ editing: false }`)에서 두 번째 인자를 넘겨야 한다. DataTable 안에 `render` 호출을 새로 만들면 반드시 인자를 넘길 것(빠뜨리면 `{ editing }` 구조분해가 터져 그 화면이 통째로 깨진다 — 실제로 겪음). 적용 완료: 교직원·Goedu 교사/학생·전자기기(묶음 4유형·개별 장비·노트북 2·보관함 2)·반별 관리 3표, 대여는 `crud={{ edit: true }}`. 관리자 표(접속 계정·동기화 기록)는 셀 편집이 없어 대상 아님. 버튼 글자는 모드와 상관없이 "수정"/"삭제" 고정(켜진 건 aria-pressed·보라색·아이콘이 ✓로 바뀌는 것으로 알린다) — "수정 완료" 같은 글자 변경은 사용자가 뺐다. 접고 펴는 영역은 CSS `.collapse`(grid 0fr↔1fr)+제목 버튼 `.tg`(aria-expanded)로 만들고, **React 18 은 `inert` 불리언을 몰라서 접힌 때만 `inert={open ? undefined : ''}` 로 붙여야** 접힌 표 안 칸에 Tab 이 안 닿는다.
10. **[2026-10-01] "드롭다운 + 기타 선택 시 직접 입력" is now a recurring request shape (Rentals quick-entry: 성함/대여물품/학년/반/번호/이름 all do this)**
   Do instead: reuse the `PickOrOther`/`OTHER`/`resolved()` pattern in `Rentals.jsx` (a `__other__` sentinel option that reveals a text input) rather than inventing a new one per field. When a student identity is built from separate 학년/반/번호 dropdowns, prefer composing the real `studentNo` (hard DB match, reuses the existing 소프트/hard-match split) over the free-typed 이름 whenever all three resolve to real numbers — only fall back to name-only (soft match) when any of the three came from "기타".

## UI Component Conventions
1. **[2026-10-02] 주 메뉴는 좌측 사이드바가 아니라 상단 바다 — 어두운 띠(사용자·로그아웃, 오른쪽) + 흰 알약 카드(브랜드·메뉴)**
   Do instead: 메뉴 이름은 "학교 정보"(예전 "교직원 검색", 카테고리는 "교직원" `/staff/contacts` · "학생" `/staff/students` — 학교 배치도는 2026-10-02 사용자 요청으로 데이터째 삭제)다 — 새 학교 정보 카테고리는 `Staff.jsx` 의 `TABS` 에 더한다. 메뉴 항목은(지금 9개, 9개 넘으면 `styles.css` 의 햄버거 접힘 폭 1000px 를 다시 재서 늘린다) `Layout.jsx` 의 `MENU`(관리자 전용 "관리자"는 별도)에만 추가한다. 홈 메뉴는 없고 브랜드("정보부 업무 관리")가 홈 링크다. 상단 바 높이는 `--topbar-h`(= 띠 32px + 카드 68px = 100px, ≤640px 90px)이고 어두운 배경은 카드 높이의 2/3 지점에서 끝난다(카드 아래 1/3 은 밝은 배경 위, `.topbar` 그라디언트)라 본문 여백이 이 변수에 묶여 있다. 폭 960px 이하는 같은 `<nav>` 가 햄버거 아래 드롭다운으로 바뀌므로(링크 클릭·Esc·바깥 클릭으로 닫힘) 메뉴를 늘릴 땐 한 줄에 들어가는지 961px 에서 확인한다. 로그아웃은 표의 "추가"와 같은 `.btn.sm.btn-toggle`(높이만 28px), 데모 배지는 카드 안 브랜드 오른쪽이다. 옛 `.sidebar`/`infodept.sidebar.collapsed` 는 없다.

1. **[2026-10-02] 버튼은 분류 클래스 하나로 만든다 — 새 버튼마다 색·모양을 새로 정하지 않는다**
   Do instead: `btn-primary`(채운 사각, 화면당 하나) · `btn-secondary`(테두리 사각) · `btn-toggle`(알약, 켜짐은 `aria-pressed`) · `btn-danger`(각진 빨강 테두리) · `btn-ghost`(밑줄 글자) 중 고른다(+ `sm`). 상태(올림·누름·포커스·사용 불가 45%)는 styles.css 의 `.btn` 규칙이 이미 갖고 있으니 개별 CSS 로 덮지 않는다. **저장 버튼은 늘 `SaveButton`**(busy → 잠김+돌아가는 원+"저장 중…", done → "저장됨", 너비 고정, 스크린리더 안내 포함) — `<button className="btn btn-primary">저장` 을 직접 쓰지 않는다. 색 있는 바탕(보라·빨강 틴트) 위 글자는 대비 4.5:1 을 직접 재서 정한다.
