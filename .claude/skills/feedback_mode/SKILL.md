# 피드백 모드

개발 서버 화면 위에서 요소를 클릭 → 메모/글자 수정을 적어 보내면 프로젝트의 `.claude/feedback.md` 에 쌓이는 도구.
전체 설명(개념·사용법·기록 형식·재사용·문제 해결)은 **`tools/feedback-mode/GUIDE.md`** 에 있다. 필요하면 그 파일을 읽는다.
소스는 `tools/feedback-mode/` (`vite-plugin.js`, `overlay.js`).

요청에 맞는 모드를 골라 실행한다. 애매하면 처리 모드로 간주하고, 파일이 없거나 비어 있으면 그렇게 말해 준다.

## 1. 처리 모드 — "피드백 처리해줘", "피드백 모드 처리해줘", `/feedback_mode`

1. `.claude/feedback.md` 를 읽는다. 없거나 `[ ]` 항목이 없으면 "처리할 피드백이 없습니다" 로 끝낸다.
2. 각 `[ ]` 항목마다:
   - `위치`(CSS 경로)·`요소` 의 클래스명·`수정` 의 원문 글자로 코드를 찾는다 (`Grep` 으로 원문 글자 / 클래스 검색).
   - `수정`(원문 → 수정문)과 `메모`를 **요청한 범위만** 최소 수정으로 반영한다. 주변 코드를 함부로 개선하지 않는다.
   - `화면` 의 창 크기가 모바일이면 모바일 레이아웃에서 확인한다.
3. **디자인 추천이 필요한 항목은 바로 고치지 않고 후보를 먼저 제안한다** (ui-ux-pro-max 스킬 연결). 대상:
   - `- 디자인 추천: 요청` 줄이 있는 항목 (패널의 "디자인 추천 받기" 체크), 또는
   - 메모가 구체적 지시가 아니라 **느낌·판단**인 항목 ("밋밋해", "답답해", "촌스러워", "색이 어색해", "더 보기 좋게", "세련되게").
   절차:
   a. 메모의 주제로 도메인을 고른다 — 색/대비 → `color`, 글꼴/글자 크기 → `typography`, 차트/그래프 → `chart`, 아이콘 → `icons`,
      여백/배치/표/터치/폼/오류 → `ux`, 분위기/스타일 전체 → `style`. React 구현 세부가 필요하면 `--stack react` 를 추가로 한 번.
   b. 영어 키워드로 검색한다 (데이터가 영어): `python .claude/skills/ui-ux-pro-max/scripts/search.py "<영어 키워드>" --domain <도메인> -n 3`
      (`python` 이 안 잡히면 `C:\Users\comsc\AppData\Local\Programs\Python\Python312\python.exe`). **`--design-system` 은 쓰지 않는다** —
      전체 테마 추천은 이 앱(교내 업무용 표·폼, 밝은 보라 테마)과 안 맞는 SaaS/글래스모피즘 쪽으로 나온다.
   c. 검색 결과를 **이 앱의 기존 토큰**(`src/styles.css` 의 `:root` — `--purple`, `--ink*`, `--surface*`, `--fs-*`, `--radius-*`)에 맞춰 번역해
      후보 2~3개를 한국어로 제시한다. 후보마다: 무엇이 어떻게 바뀌는지 한두 줄 + 근거(검색 결과의 Do/Don't 또는 스타일 키워드).
      새 색·새 폰트를 끌어오는 후보보다 기존 토큰 안에서 해결하는 후보를 먼저 둔다.
   d. 사용자가 고르면 그 후보만 반영한다. 고르기 전까지 항목은 `[ ]` 로 두고 `- 제안: 후보 N개 제시, 선택 대기` 를 덧붙인다.
4. 요청이 **화면이 아니라 데이터**(메뉴얼 본문·비고·명단·시트 값)면 코드를 고치지 말고, 앱의 셀 편집/시트 수정으로 하라고 안내한다. 항목은 `[x]` 로 닫고 "데이터라 코드 수정 안 함" 이라 적는다.
5. 요청이 모호하거나 서로 충돌하면 추측해서 고치지 말고 그 항목만 사용자에게 묻는다. 그 항목은 `[ ]` 로 남긴다.
6. 처리한 항목은 `- 상태: [ ] 처리 전` 을 `- 상태: [x] 처리됨 — 한 줄로 무엇을 어느 파일에서 했는지` 로 바꾼다.
7. 가능하면 변경한 화면을 실제로 열어 확인한다(프로젝트에 헤드리스 Chrome 검증 방식이 있으면 그것을 사용). 확인하지 못했으면 "확인 못 함" 이라 말한다.
8. 끝나면 항목별로 무엇을 했는지 짧게 요약한다.

## 2. 안내 모드 — "피드백 모드가 뭐야", "피드백 모드 사용법"

`tools/feedback-mode/GUIDE.md` 의 2번(사용법)을 중심으로 요약해 알려 준다. 핵심 한 줄: 개발 서버 우하단 "피드백" 버튼 → 요소 클릭 →
메모/글자 수정 → 보내기 → `.claude/feedback.md`. 끄기는 Esc. 데이터 수정은 범위 밖(셀 편집 사용).
보낸 뒤에도 저장 직후 알림의 "보기·수정" 또는 우하단 "보낸 목록"에서 처리 전 항목을 다시 보고 고치거나(수정) 지울 수 있다(처리된 `[x]` 항목은 읽기만).

## 3. 설치 모드 — "이 프로젝트에도 피드백 모드 넣어줘"

대상이 **Vite 기반** 프로젝트인지 먼저 확인한다 (`vite.config.*` 존재). 아니면 `GUIDE.md` 7번 마지막 문단대로 서버 미들웨어를 따로 만들어야 함을 알린다.

0. 대상 프로젝트에 `.claude/skills/ui-ux-pro-max/` 가 없으면 "디자인 추천 받기" 는 동작하지 않는다 (체크해도 기록만 남고 Claude 가 일반 메모로 처리).
   필요하면 사용자가 터미널에서 `npx --yes ui-ux-pro-max-cli init --ai claude` 로 설치하도록 안내한다 (Python 3 필요). Claude 가 직접 실행하면 외부 코드 실행으로 막힐 수 있다.
1. `tools/feedback-mode/` 폴더(`vite-plugin.js`, `overlay.js`, `README.md`, `GUIDE.md`)를 대상 프로젝트의 같은 위치로 복사한다.
   이 프로젝트의 원본 경로: `c:\Users\comsc\OneDrive\바탕 화면\code\info department\tools\feedback-mode\`.
2. 대상 `vite.config.*` 에 `import feedbackMode from './tools/feedback-mode/vite-plugin.js'` 와 `plugins` 배열에 `feedbackMode()` 를 추가한다 (기존 설정 유지).
3. 대상 진입점(`main.jsx`/`main.tsx`/`main.js` 등) 맨 아래에 다음 줄을 추가한다 (상대 경로는 진입점 위치에 맞춘다, `app` 은 그 앱 이름):
   ```js
   if (import.meta.env.DEV) import('../tools/feedback-mode/overlay.js').then((m) => m.mountFeedbackMode({ app: '앱 이름' }));
   ```
4. 대상 `CLAUDE.md` 에 한 줄 추가: "세션 시작 때 `.claude/feedback.md` 에 `[ ]` 항목이 있으면 먼저 처리한다". CLAUDE.md 가 없으면 만들지 말고 사용자에게 어디에 둘지 묻는다.
5. 대상 프로젝트에서도 `/feedback_mode` 를 쓰려면 이 스킬 폴더(`.claude/skills/feedback_mode/`)를 복사한다. 모든 프로젝트에서 쓰려면 `~/.claude/skills/feedback_mode/` 로 복사하도록 권한다 (사용자 홈 폴더를 건드리므로 먼저 확인).
6. 확인: 개발 서버에서 `/__feedback` 이 `{"file":...,"open":0}` 을 돌려주는지, 화면 우하단에 "피드백" 버튼이 보이는지 본다.
   `npm run build` 산출물에 `fbm-root` 가 없는지도 확인한다 (배포 제외 보장).

## 지켜야 할 것

- 피드백 모드는 **개발 서버 전용**이다. 배포 빌드에 들어가게 만들지 않는다 (`apply: 'serve'`, `import.meta.env.DEV`).
- `.claude/feedback.md` 를 테스트하려고 가짜 항목을 넣었다면 끝나기 전에 지운다 (진짜 사용자 요청과 섞이지 않게).
- 글자 미리보기는 DOM 변경일 뿐이다. 실제 반영은 항상 코드 수정으로 한다.
