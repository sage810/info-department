# lesson-teacher — 교사용 화면 · 정답지 PDF

## 교사용 화면 (진행률 위젯 없음)

따로 만들 필요 없다. `npm run build` 가 모든 차시마다 자동으로 만든다.
- GitHub Pages: `…/<단원>/<차시>/teacher.html`
- 구글 사이트 붙여넣기용: `dist/embed/<단원>-<차시>.teacher.html`
교사용 화면에서는 "제출"이 선생님 드라이브로 가지 않는다.

## 정답지 PDF

1. `lessons/<단원>/<차시>/answers.json` 을 채운다(없으면 만든다).
   ```json
   {
     "name": "교사용 정답지",
     "fill":  { "M2 이상치 용어 빈칸 1": "이상치", "M2 그래프 해석": "…" },
     "click": [ { "near": "1. 우리 반 친구들이 좋아하는 계절", "text": "구성 분석" } ]
   }
   ```
   - `fill` 키 = 빈칸의 `aria-label` (Grep `aria-label="M` 으로 목록 확인).
   - 정답은 활동지 본문·`spec.md`·`answers.md`·선생님이 준 답에서 **그대로 옮긴다. 추측해서 쓰지 않는다.** 모르면 묻는다.
   - 서술형(그래프 해석·나의 결정)은 선생님이 준 예시 답이 있을 때만 넣는다. 없으면 비워 두고 알린다.
   - `click` 은 형성평가처럼 눌러야 하는 것: `near` = 문항 글자 앞부분(번호 포함하면 헷갈림이 없다), `text` = 버튼 글자 그대로.
2. `npm run teacher -- <차시>` → `dist/answers/<단원>-<차시>-정답지.pdf`
3. 출력의 △ 를 확인한다.
   - "정답이 안 적힌 빈칸" → answers.json 에 빠진 것
   - "활동지에는 없는 빈칸" → aria-label 이 바뀌었거나 옛 판
   - "누르지 못한 버튼" → near/text 글자 확인
4. 만든 PDF 를 Read 도구로 몇 쪽(`pages` 지정) 열어 정답이 제자리에 들어갔는지 확인하고, 파일 위치를 알려 준다.

PDF 는 활동지 안의 "PDF로 저장하기" 버튼을 그대로 눌러 만든다 — 학생이 받는 PDF 와 모양이 같다.
그래서 이름 미입력·진행률 부족 가드가 있는 차시는 `name` 과 충분한 정답이 있어야 통과한다.
